The old `silicon-refund-verify` route returned HTTP 404; its Vercel project deploys this repository,
which has no verification backend. More fundamentally, Apple's
[Get Refund History](https://developer.apple.com/documentation/appstoreserverapi/get-refund-history)
describes in-app purchases, not refunds of the original paid app. The unsupported call and its
Xcode reference have been removed. Founding Owner eligibility keeps the verified production
AppTransaction and the unchanged build-5 boundary. This preserves the previous fail-open access
behavior without sending an original app receipt to a dead endpoint. It does **not** claim to
detect refunded paid-app downloads. StoreKit/RevenueCat subscription and non-consumable
revocation checks remain in place.

Both privacy-page sources and the manifest commentary reflect the removed request. The pages
also clarify that RevenueCat initializes before a purchase; an anonymous installation ID and
purchase-status checks are possible for non-buyers. The corrected hosted privacy page is live
and returns HTTP 200. The in-app paywall links to that hosted page. The public App Privacy labels
were checked; account-level RevenueCat integration and retention settings remain unverified.

## Device test handoff

On the exact TestFlight build, record iPhone/iPad model, OS and build:
- Upgrade an existing populated save; verify purchases, finishes, staff and furniture placements, restart and background/resume persistence.
- Exercise fresh and crowded offices in both themes: camera gestures, Shop, Decorate move/rotate/place/reject/cancel/Undo, exit/reload; inspect robot walking, sofa and watering interactions and Reduce Motion.
- Run a connected factory through productive weeks; edit/Undo, save/reload and confirm ownership and cash accounting.
- Exercise subscription purchase, restore, cancellation and legacy entitlement behavior with the existing StoreKit test matrix.
- Sustain office/factory navigation and repeated screen changes; record stutter, artifacts, context loss and thermal behavior.

Software-rendered Windows browser checks are not device performance evidence. Individual use animations for additional chair/sectional types remain outside this candidate. Uploading to TestFlight does not certify App Store readiness or close physical-device, purchase, privacy/account or release-checklist gates.
