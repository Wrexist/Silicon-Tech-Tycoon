# Building Silicon for iOS

The committed Capacitor project is `ios/App/App.xcodeproj`, scheme `App`. It uses Swift Package Manager, including RevenueCat. Do not recreate it with `cap add ios` or introduce CocoaPods.

## Local build on macOS

Use Node 22 and Xcode 26 or later with the iOS 26 SDK or later, per [Apple's upload requirements](https://developer.apple.com/news/upcoming-requirements/?id=04282026a).

```sh
npm ci
node scripts/verify-release-version.mjs
npm run typecheck
npm test -- --maxWorkers=2
node appstore/localizations/validate.mjs --all
npm run build
npx cap sync ios
open ios/App/App.xcodeproj
```

Select scheme `App`, the existing signing team and a device. Bundle ID: `com.wrexist.silicon`. Preserve universal iPhone/iPad support (`TARGETED_DEVICE_FAMILY = "1,2"`), portrait on iPhone and all four iPad orientations. The deployment target is iOS 15. Test representative supported hardware; Windows browser checks cannot validate native performance or StoreKit.

After every web change, rebuild and sync before archiving. `CapApp-SPM/Package.swift` is regenerated by Capacitor; RevenueCat belongs to the Xcode app target instead.

The `iOS TestFlight` workflow runs `.github/workflows/release-gates.yml`, then builds, signs, exports and uploads on macOS. Existing repository secrets hold the App Store Connect key; never copy private keys into the project.

An upload is not a review submission. Confirm processing, test the exact build on iPhone/iPad, validate purchase/restore and upgrade saves, then attach that build to the 1.4.0 store version.

## Store configuration

- The app is free to download with Silicon Pro monthly/yearly subscriptions and a lifetime purchase. Keep legacy Creative Mode restorable. Actual prices and offers come from StoreKit; verify live products and RevenueCat entitlement configuration.
- Native purchases use `SiliconStoreKit.swift`, `SiliconStoreKit+RevenueCat.swift` and `RevenueCatConfig.swift`; the shared JS bridge is `src/state/storeKitBridge.ts`.
- RevenueCat processes purchase data. Do not declare "Data Not Collected". Reconcile the privacy manifest, hosted policy and live App Privacy answers with actual collection and linkage.
- Use `appstore/localizations/` for store fields and validate all locales. Confirm screenshots depict this candidate on each supported device family.
- Complete current age-rating, account, export-compliance and review-contact fields in App Store Connect using verified information.

See `appstore/SUBSCRIPTION_GUIDE.md` for purchase tests and `docs/releases/1.4.0.md` for device checks. Historical checklists do not prove live settings or physical-device tests have passed.
